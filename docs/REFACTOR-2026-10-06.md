# Userscripts 全面優化重構紀錄（2026-10-06）

- 分支：`refactor/userscripts-optimization-2026-10`
- 基準：`main`（`6fb8486`）
- 範圍：`src/` 底下全部 72 個檔案（71 支 userscript 加上 `AvoidClosingTab.ahk`），以及打包腳本對應的 `dev/Readability/` 原始碼。`src/archived/` 不在範圍內。
- 結果：76 個 commit。69 支腳本遞增了版本；ChatGPTVoiceInput 與 SimplifiedToTraditionalChinese 經分析後不修改。

## 原則

本次重構以「不造成 Breaking Changes」為最高原則。下列項目一律不改：

- `@name` 與 `@namespace`。Tampermonkey 以這兩個欄位識別腳本，改了就會變成另一支腳本，使用者的設定也會遺失。
- 檔名與 `@source`。使用者從 `raw/main/src/<檔名>` 安裝，Tampermonkey 也以安裝網址檢查更新。唯一的例外是 `104HideSidebar.js`：它的 `@source` 原本就指向 `.user.js`，見下方說明。
- `@match`、`@include`、`@exclude` 的實際涵蓋範圍。
- 快速鍵組合、選單文字、預設行為、輸出格式（例如複製出來的 Markdown、送給 Gemini 的 prompt 語意）。
- `localStorage`、`GM_setValue` 等儲存鍵名與資料格式。

可以做的調整依優先順序為：

1. 修正實際 bug：例外、null 存取、競態、事件重複註冊、計時器或 observer 洩漏、SPA 換頁後失效。
2. 安全性：XSS、Trusted Types 相容、憑證外洩。
3. 效能：observer 範圍與成本、無限輪詢。
4. 健壯性：快速鍵在輸入情境與 IME 組字時要忽略、修飾鍵衝突。
5. Header 規範化：依 `AGENTS.md` 調整欄位順序；沒用到 GM API 的腳本明確宣告 `@grant none`。
6. 清理除錯輸出與死碼。

依 `AGENTS.md` 的「Automated Intent & Commenting Policy」，所有修改或新增的程式碼都附上繁體中文的意圖註解。

每支有改動的腳本都遞增 `@version`，讓已安裝的使用者能收到更新：一般修正遞增 patch，有使用者可感受的強化則遞增 minor。

## 方法與驗證

- 72 個檔案依網站與性質分成 6 組，逐支完整閱讀並分析。每支腳本一個 commit；少數大型腳本有多個彼此獨立的優化，拆成多個 commit。每個 commit 訊息都以繁體中文詳細記錄：背景、變更、相容性說明、驗證方式與版本。
- 每支改過的檔案都通過 `node --check`；整個分支通過 `git diff --check`，沒有 CRLF 或行尾空白。
- 純邏輯與 DOM 行為的修改，都以 node、jsdom 撰寫臨時測試，比對新舊版行為。不少測試以舊版重現了原本的 bug，再確認新版已修正。測試腳本不納入 repo。
- 打包腳本只改 `dev/` 原始碼，再以 `npm run build` 產生 `src/` 輸出，並確認重建結果與 commit 內容逐位元組相同。`dev/Readability` 新增了可以實際執行的 `npm test`。
- 分支層級的檢查：
  - 以程式比對 `main..HEAD`，確認所有腳本的 `@name`、`@namespace`、`@source`、`@match`、`@include`、`@exclude` 完全未變。
  - 每支有改動的腳本都已遞增 `@version`。
  - 新加 `@grant none` 的腳本都沒有使用任何 GM API 或 `unsafeWindow`。
- **限制：所有修改都還沒在真實網站上手動驗證。** 本次沒有開瀏覽器測試，也沒有發送任何 Gemini 或 Azure 請求。各腳本段落的「手動驗證建議」列出上線前應檢查的項目。

## 審查時做出的決策

以下是審查各組修改時，為了守住「不造成 Breaking Changes」而做的取捨，已反映在 commit 中：

1. **CopyToMarkdown 保留「不選取直接複製整篇文章」**。原本的修改把「沒有選取內容時以 Readability 擷取整頁」整個移除，這等於移除既有功能，因此改為：
   - 只有使用者剛以鍵盤按下 Ctrl+C 或 Cmd+C（1 秒內）、而且沒有選取時，才走整頁後備；
   - 在 `<input>`、`<textarea>` 內複製，以及網站一鍵複製按鈕觸發的程式化複製，一律不接手。
2. **YouTubeDownloadSubtitle 保留「原樣放行」的 Trusted Types `default` policy 作為相容層**。按鈕本身已改用 DOM API 建立，不再需要 policy。但 default policy 是整個 YouTube 頁面共用的，其他在 YouTube 上直接指派 `innerHTML` 的腳本（包含第三方腳本）可能依賴它，因此照舊版時機繼續建立，並加上 try/catch 防護。
3. **AzureDevOpsWikiFloatingTOC 的 `@homepage`、`@homepageURL`、`@website` 維持原值（GitHub）**，依 `AGENTS.md`「除非擁有者變更，否則保持不變」的規範。
4. **SavePageToAzureBlob 的快照不再收錄密碼欄位的值**。快照會發佈到可公開讀取的 Blob URL，把已輸入的密碼寫進快照等於公開密碼。這屬於必要的安全修正，不視為 Breaking Change。
5. **SelectionToMarkdownContextMenu 的版本採 1.9.1**，而不是 dev header 上未發佈的 1.9.0。這樣在本機建置並安裝過含除錯輸出 1.9.0 的人，也能收到更新。
6. **`104HideSidebar.js` 改名為 `104HideSidebar.user.js`**（commit `ba6f02c`），讓檔名與早已寫在 header 中的 `@source`、`@namespace` 一致。原本的 `.js` 網址無法觸發 Tampermonkey 安裝，README 也沒有連結到它，因此不影響任何使用者。

## 待作者決定的事項

以下是分析時發現、但修正會改變涵蓋範圍、行為或架構的問題，本次刻意保留，需要作者決定：

### 已失效或不會執行的腳本

- **ChatGPTVoiceInput**：`@match` 只涵蓋 `chat.openai.com`，該網域已轉址到 `chatgpt.com`，DOM 結構也不相容（textarea 已換成 ProseMirror）。直接擴充 `@match` 會每 300ms 丟一次例外，並反覆要求麥克風權限。建議封存或重寫。
- **ChatGPTAutoFill、ChatGPTCommonPrompts、ChatGPTDoubleClickEdit、ChatGPTSummaryPage、ChatGPTTranslationE2T、ChatGPTTranslationT2E**：同樣受網域轉址與 DOM 改版影響。三支右鍵選單腳本都依賴 ChatGPTAutoFill。本次只修程式錯誤，沒有改 `@match` 或網址。
- **GoogleAiStudioLightTheme**：`@match` 的 `makersuite.google.com` 已轉址到 `aistudio.google.com`。

### `@match` 涵蓋範圍

- **AzureDevOpsWikiFloatingTOC**：只涵蓋 `https://*.visualstudio.com/*/_wiki/*`。dev.azure.com 的 Wiki 不會載入，從其他頁面以 SPA 切進 Wiki 也不會注入。
- **GoogleAppsScriptHideWarningBar**：`.../macros/s/*/exec` 結尾沒有 `*`，帶查詢字串的網址與 Workspace 網域的 `/a/macros/...` 可能都沒有套用到。
- **FBRemoveShop**：`@source` 與 `@namespace` 指向不存在的 `src/RemoveFBShopButton.user.js`。`@namespace` 不能改；`@source` 要不要修正，由作者決定。

### 行為或架構

- **SavePageToAzureBlob**：右鍵橋接事件 `save-page-to-azure-blob:trigger` 可以被任何網頁偽造，讓使用者在不知情下以自己的 SAS 擷取並發佈該頁，雖然 SAS 本身不會外洩。可行的緩解是：只在最近一次真實右鍵之後數秒內接受觸發，或觸發前先確認。但這可能影響在 iframe 內按右鍵的用法。另外，設定 SAS 的對話框會預填目前的 SAS URL。
- **CopyToMarkdown**：`GM_setClipboard()` 在 `event.clipboardData.setData()` 之後無條件執行，可能以只有 text/plain 的內容覆寫剪貼簿，讓 text/markdown 與 text/html 失效。需要在瀏覽器實測確認。
- **TrackingTokenStripper**：
  - 規則寫的是小寫 `wt.mc_id`，而 URLSearchParams 區分大小寫，所以 Microsoft 網站常見的 `WT.mc_id` 不會被移除。
  - Facebook 的 `ref` 規則看起來是想只移除 `ref=notif`，實際效果卻是移除所有 `ref`。
  - 兩者都維持既有行為。
- **YouTubeSubtitleGeminiTranslator**：
  - 腳本有宣告 GM API，在 Tampermonkey 沙箱中 `window.fetch = ...` 可能改不到頁面本身的 fetch，屬於架構問題。
  - API Key 改放在 `x-goog-api-key` header，這是 Gemini 官方文件的寫法，但只用 mock 驗證過，建議以真實金鑰實測一次。
- **YouTubeDownloadSubtitle**：保留的原樣放行 default policy 會讓 YouTube 的 Trusted Types 防護失效。確認沒有腳本依賴它之後，建議在後續版本移除。
- **ImmersiveTranslateAutoFix**：為了相容 Trusted Types 網站，建立了一個具名、只在腳本內部使用的原樣放行 policy，只用於由既有 DOM 序列化而來的 HTML。若不接受這個做法，可以改為在這類網站略過跨標籤修正。
- **BlurKeywords、AddSpaceBetweenChineseAndEnglish**：沒有排除 contenteditable。排除可以避免與編輯器互相觸發，代價是失去「編輯中的內容也會處理」的效果。
- **LocalStorageTransfer**：沒有加 `@noframes`，選單命令可能在每個 iframe 重複註冊；但 iframe 的 localStorage 可能正是偵錯對象。
- **FormSnapshotHumanLikeRefill**：找不到選單內的搜尋框時，會退回頁面上任何可見的搜尋框，可能把選項文字打進網站本身的搜尋列；但 select2 一類元件可能正依賴這條退路。
- **SavePageToAzureBlob**：複製出來的 `<script>` 以 `textContent` 改寫，在強制 Trusted Types 的網站上可能丟例外。

### 刻意做出、使用者看得到的行為差異（上線前請確認）

- AzureDevOpsDarkModeSwitcher：macOS 的 Option+S 現在可以觸發，原本因為 `ev.key` 是「ß」而完全無效；Ctrl+Alt+S（Windows AltGr）不再觸發。
- AzureDevOpsHotkeys：首頁按 j 到最後一列時，一次就繞回第一列；Ctrl+B 只在確實切換側邊欄時才 `preventDefault`。
- AzureDevOpsEnableKeyboardShortcuts：`@run-at` 改為 `document-start`，當次載入就生效。
- GeminiToggleAudioInput：macOS 的 Option+T 改以 `event.code` 偵測，現在可以使用。
- JinaReader：加上 `@noframes`，焦點在 iframe 時按快速鍵會回到瀏覽器的預設行為；在 r.jina.ai 上不再重複套用。
- OpenAIHotkeys：第一次按 f 時，main 後方的區塊也會一起隱藏，這是修正 `previousElementSibling` 的筆誤。
- SinoBankMMASignIn：同網域的子 frame 也會解除事件封鎖。這是原本的程式意圖，但因 `arguments.callee` 在嚴格模式下失效而一直沒有生效。
- PDFXChangeNewClientAutoFill：`waitForElement` 有傳選項但沒有指定逾時時，上限改為 30 秒（原本是無限等待）。
- TrackingTokenStripper：sendgrid.com 上的 `mc`、`mcd`、`cvosrc` 參數現在真的會被移除（1.14 誤用了 `remove()`）。

## 各腳本分析

以下依分組列出每支腳本的分析結果，包含沒有修改的腳本。每支腳本的段落都有以下項目：

- 分析：發現的問題
- 調整：實際做的修改
- 刻意未調整：可以改、但可能造成 Breaking Change 或風險而保留的地方

### 一、Azure DevOps／Azure Portal／Microsoft 系列（14 支）

本組共 14 支腳本，全部有調整（皆為一支腳本一個 commit，無拆分）。驗證方式：每支皆通過 `node --check` 與 `git diff --check`；12 支以 jsdom（`dev/Readability/node_modules/jsdom`）撰寫臨時行為測試，其中 5 支同時對舊版執行同一組測試以重現原始 bug；MVPDocsLearnChampionProgram 以 node 比對新舊版網址輸出；AzurePortalMask 另做效能基準測試。測試程式為臨時腳本，未加入 repo。

#### AzureDevOpsDarkModeSwitcher
- 檔案：`src/AzureDevOpsDarkModeSwitcher.user.js`
- 版本：0.1.0 → 0.1.1
- 分析：
  - 快速鍵只排除 `input/select/textarea/button`，在 New Boards Hub 的 contenteditable 編輯器（工作項目描述、討論）中按 Alt+S 會切換主題並 `location.reload()`，未儲存的內容遺失。
  - macOS 的 Option+S 會讓 `ev.key` 變成「ß」，快速鍵在 Mac 上永遠不會觸發。
  - 沒有忽略 IME 組字、沒有排除 Ctrl/Meta 修飾鍵、沒有 `preventDefault()`（Windows 版 Firefox 的 Alt+S 會開啟「歷史」選單）、沒有處理 `ev.repeat`。
  - `run()` 是 async 但 `fetch()` 沒有被 await；連按會重複送出 PATCH。
  - 找不到 token 時送出 `authorization: Bearer undefined`，必定 401。
  - 沒有 `@grant`。
- 調整：
  - 新增 `shouldIgnoreTarget()`（加上 contenteditable）與 `isComposing` 檢查；同時按 Ctrl/Meta 不處理。
  - 新增 `getKeySCase()`：`ev.key` 為 s/S 時維持原判斷；`ev.key` 不是英文字母時才改用 `ev.code === 'KeyS'`（Shift/CapsLock 判斷大寫），讓 macOS 可用且不影響 Dvorak 等配置。
  - 接手後 `preventDefault()`、略過 `ev.repeat`；以 `isSwitching` 旗標防止重複請求；改為 await 並統一 try/catch，錯誤訊息加前綴與 HTTP 狀態碼。
  - 沒有 token 時省略 authorization 標頭，改由 `credentials: 'include'` 的 Cookie 驗證。
  - body 改用 `JSON.stringify()`（輸出逐字相同）；`#dataProviders` 改用 `textContent`。
  - 補上 `@grant none`。
- 刻意未調整：
  - 寫死的 `accept-language` 標頭與 `api-version=4.1-preview.1`（自 DevTools 複製，與 API 行為無關，改動無益）。
  - 以掃描 localStorage 找 Bearer token 的做法（依賴 Azure DevOps 內部儲存格式，但目前可用）。
- 手動驗證建議：在 dev.azure.com 與 *.visualstudio.com 以 Windows 與 macOS 各按一次 Alt+S，確認主題切換並重新載入；在工作項目描述（contenteditable）中按 Alt+S 不會重新載入；開啟 CapsLock 按 Alt+S 會出現提示。**macOS 的 Option+S 支援是新行為，需實機確認。**
